## 1. The JTBD Methodology in Sidra OS

In Sidra OS, a Job To Be Done (JTBD) defines the underlying operational goal a user is trying to accomplish during their workday, independent of specific user interface mechanics. 

Every JTBD follows the standard high-trust strategic format:
> **"When [Operational Context/Situation], I want to [Delegate Intent/Action], so that [High-Value Outcome/Benefit]."**

---

## 2. Persona JTBD Matrices

### 2.1 The Founder
* **JTBD 1 (Strategic Execution):** When I have a vision for a new product initiative, I want to issue a single high-level intent statement to Sidra OS, so that synthetic product, engineering, and marketing departments build, test, and market the initiative with audited quality.
* **JTBD 2 (Investor Updates):** When monthly reporting is due, I want Sidra OS to synthesize company financial, engineering, and product progress into an audited investor memo, so that I maintain investor trust with zero manual document writing.
* **Daily Cadence:**
  * *Morning:* Review Executive Daily Brief; sign off on 2-3 key strategic decisions.
  * *Mid-day:* Issue 1 strategic intent for product evolution; inspect agent department progress.
  * *End-of-day:* Review audited brief outputs; verify runway and expenditure ledger.

---

## 2.2 Chief Executive Officer (CEO)
* **JTBD 1 (Cross-Department Alignment):** When cross-functional initiatives are in flight, I want an aggregated executive summary highlighting operational risks and blockers, so that I can unblock bottlenecks without attending 5 daily standup meetings.
* **JTBD 2 (High-Stakes Decision Making):** When faced with a critical strategic pivot, I want structured options briefs with independent risk reviews, so that I make data-backed, sovereign decisions with clear audit logs.
* **Daily Cadence:**
  * *Morning:* Scan Executive Alignment Brief; approve strategic decision records (ODRs).
  * *Mid-day:* Query organizational memory for historical context on key enterprise partnerships.
  * *End-of-day:* Validate quarterly objective trajectory and department output velocity.

---

## 2.3 Chief Operating Officer (COO)
* **JTBD 1 (Process Bottleneck Elimination):** When a department's execution slows down, I want to inspect the workflow topology log in Sidra OS, so that I identify whether the bottleneck is capability, budget, or context-related.
* **JTBD 2 (Governance & Capability Fencing):** When granting synthetic departments external tools, I want to configure hard budget and action fences, so that no agent exceeds financial or security boundaries.
* **Daily Cadence:**
  * *Morning:* Audit department throughput metrics; inspect active resource allocations.
  * *Mid-day:* Adjust budget ceilings and tool permissions for high-priority projects.
  * *End-of-day:* Verify that all departmental operations complied with governance rules.

---

## 2.4 Chief Technology Officer (CTO)
* **JTBD 1 (Architecture Governance):** When engineering agents draft code, I want automated adherence checks against our system architecture invariants (ADRs), so that code quality and safety remain flawless.
* **JTBD 2 (Security & Vulnerability Auditing):** When new services are generated, I want independent security reviewer agents to attempt exploit vectors locally, so that vulnerabilities are caught before production deployment.
* **Daily Cadence:**
  * *Morning:* Review System Architecture Brief; approve pending ADR changes.
  * *Mid-day:* Inspect automated code audit logs and test coverage metrics.
  * *End-of-day:* Review local repository index health and synthetic developer throughput.

## 2.5 Project Manager / Product Manager (PM)

* **JTBD 2 (Sprint Verification):** When a feature build completes, I want automated QA reviewer agents to test all user paths against the spec, so that releases ship with zero manual QA overhead.
* **Daily Cadence:**
  * *Morning:* Review Sprint Velocity Brief; approve functional specs.
  * *Mid-day:* Inspect feature execution graphs and refine product boundary constraints.
  * *End-of-day:* Validate release candidate briefs and auto-generated changelogs.

## 2.6 Developer / Software Engineer
* **JTBD 1 (Flow State Maintenance):** When implementing complex algorithms, I want synthetic engineering staff to write unit tests and documentation in the background, so that I remain uninterrupted in flow state.
* **JTBD 2 (Local Repository Intelligence):** When working on legacy modules, I want to query local codebase memory instantly, so that I understand past architectural decisions without manually reading thousands of files.
* **Daily Cadence:**
  * *Morning:* Pull engineering task brief; review auto-generated boilerplate and test drafts.

  * *End-of-day:* Approve clean git commits generated by audited synthetic dev agents.
