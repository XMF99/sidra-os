## 2. Detailed Actor Specifications

### 2.1 Human Actor Classifications

#### Actor H-01: Founder / CEO
* **Responsibilities:** Intent declaration (`Cmd+K`), strategic approvals, executive brief sign-offs, reserved power execution.
* **Permissions:** Full Root Governance; Unanimous Board Resolution voting; Multi-sig initiation.
* **Goals:** Maximum company output velocity with zero administrative drag.
* **Relationships:** Delegates missions to Synthetic Executive Agents; reviews briefs compiled by `mission::brief_compiler`.

#### Actor H-02: CTO / Engineering Lead
* **Responsibilities:** Architecture Decision Record (ADR) sign-offs, technical fence configuration, system code audit review.
* **Permissions:** Technology & Architecture Domain Root; Git Release sign-off; ADR approval.
* **Goals:** Zero architectural debt, 100% test coverage, flawless code security.
* **Relationships:** Supervises Synthetic Dev Agents; approves briefs from Independent Security Reviewers.

#### Actor H-03: CFO / Finance Lead
* **Responsibilities:** Department compute budget ceiling adjustments, financial brief approvals, invoice reconciliation.
* **Permissions:** Financial Domain Root; Token Budget override; Ledger reconciliation view.
* **Goals:** Predictable operational burn rate, zero compute budget overruns.
* **Relationships:** Monitors budget alerts from `finance::budget_manager`.

#### Actor H-04: Developer / Software Engineer
* **Responsibilities:** Core logic implementation, PRD specification review, local code flow state.
* **Permissions:** Repository Read/Write; Local Task execution; Code diff sign-off.
* **Goals:** Uninterrupted flow state, zero tedious boilerplate writing, rapid debugging.
* **Relationships:** Directs Synthetic Dev Agents; reviews drafts generated by Author agents.

#### Actor H-05: IT Administrator / CISO
* **Responsibilities:** User SCIM provisioning, hardware TPM key management, enterprise fleet policy enforcement.
* **Permissions:** Administration & Security Domain Root; User provisioning; Remote workspace revocation.
* **Goals:** Flawless enterprise compliance, zero data breaches, automated identity sync.
* **Relationships:** Manages accounts in `identity::directory`; enforces policies in `governance::pbac`.

#### Actor H-06: External Auditor / Compliance Officer
* **Responsibilities:** Regulatory compliance evidence collection, legal hold configuration, immutable ledger verification.
* **Permissions:** Compliance Domain Read-Only Root; Cryptographic Audit Log verification.
* **Goals:** Rapid SOC 2 / ISO 27001 audit completion with zero data tampering risks.
* **Relationships:** Queries verification evidence from `compliance::auditor`.

### 2.2 AI Actor Classifications (Synthetic Agents)

#### Actor AI-01: Synthetic Author Agent
* **Responsibilities:** Drafting code diffs, PRDs, marketing copy, and financial models within assigned department charters.
* **Permissions:** Bounded workspace sandboxes; Read access to assigned mission context (**INV-05**).
* **Goals:** High-quality, fast task drafting matching enterprise standards.
* **Relationships:** Dispatched by `mission::intent_parser`; **CANNOT review or approve own output (**INV-02**)**.

#### Actor AI-02: Independent QA Reviewer Agent
* **Responsibilities:** Running automated unit/fuzz tests, verifying PRD spec compliance, calculating code coverage.
* **Permissions:** Test runner execution; Read access to code diffs; Audit report generation.
* **Goals:** Catching edge-case bugs and spec violations before human presentation.
* **Relationships:** Audits outputs from Synthetic Author Agents; reports to `mission::brief_compiler`.

#### Actor AI-03: Independent Security Reviewer Agent
* **Responsibilities:** Static security vulnerability scanning, capability fence checking, dependency vulnerability audits.
* **Permissions:** Read-only access to code diffs and environment specs; Security audit reporting.
* **Goals:** Zero security vulnerability leaks or unauthorized API egress attempts.
* **Relationships:** Audits Author outputs independently (**INV-02**); flags risks in Executive Briefs.

#### Actor AI-04: Executive Synthetic Coordinator
* **Responsibilities:** Decomposing missions, routing tasks across synthetic departments, tracking project velocity.
* **Permissions:** Mission graph creation; Department task assignment; Context retrieval.
* **Goals:** Smooth multi-agent execution coordination without human micro-management.
* **Relationships:** Receives intent from Human CEO (`Cmd+K`); orchestrates Author and Reviewer agent pools.

### 2.3 System Actor Classifications

#### Actor SYS-01: THEKY Local Kernel Process
* **Responsibilities:** Application bootstrap, inter-process communication (IPC) pipe management, OS hardware interface.
* **Permissions:** OS Ring 1 Kernel IPC privileges; Memory vault mounting.
* **Goals:** Sub-30ms application launch, sub-50ms UI response latency (**INV-06**).
* **Relationships:** Manages life cycle of all local application modules.

#### Actor SYS-02: Local Vector Indexer
* **Responsibilities:** Background text chunking, local ONNX vector embedding generation, HNSW index updates.
* **Permissions:** Read-only access to local Markdown files; Local VRAM/NPU allocation.
* **Goals:** Real-time semantic memory index freshness with zero battery drag.
* **Relationships:** Indexes documents written by `knowledge::docstore`.

#### Actor SYS-03: Hash Ledger Writer
* **Responsibilities:** Cryptographic SHA-256 block calculation, block signing, append-only ledger storage.
* **Permissions:** Append-only access to `hash_ledger.jsonl`; Hardware TPM signing key access.
* **Goals:** 100% cryptographic ledger integrity (**INV-03**).
* **Relationships:** Listens for event emissions from all system domains.

---

### 2.4 External Actor Classifications

#### Actor EXT-01: Enterprise IdP (Entra ID / Okta)
* **Responsibilities:** SAML 2.0 / OIDC identity assertion, SCIM 2.0 real-time user provisioning.
* **Permissions:** Identity assertion provider; Zero access to local workspace data.
* **Goals:** Centralized enterprise user lifecycle management.
* **Relationships:** Syncs identity records with `identity::directory`.

#### Actor EXT-02: Cloud Frontier LLM Provider (OpenAI / Anthropic)
* **Responsibilities:** Remote model inference execution for Layer 4 cloud bursts.
* **Permissions:** Scoped API token access; Receives policy-cleared prompt payloads (**INV-05**).
* **Goals:** High-reasoning model outputs for ultra-complex tasks.
* **Relationships:** Invoked by `ai::router` proxy adapter.

#### Actor EXT-03: Enterprise SIEM Collector (Splunk / Datadog)
* **Responsibilities:** Real-time security event log ingestion.
* **Permissions:** Outbound TLS 1.3 audit log stream ingestion endpoint.
* **Goals:** Centralized enterprise security monitoring.
* **Relationships:** Receives streamed logs from `admin::siem_streamer`.
